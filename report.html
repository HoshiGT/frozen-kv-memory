00指标

一个比值，量纲是 nats。三个条件下让模型预测同一段后续文本，唯一区别是它能看见什么。

upper  段 B 看见前 512 token 的全部 KV  ← 什么都没丢
lower  段 B 什么都看不见  ← 全丢了
comp  段 B 只看见 k 条压缩后的 KV

recovery = (lower − comp) / (lower − upper)

1.0 表示在该预算下无损，0 表示这些槽位白给。 超过 1.0 是可能的：记忆槽是朝「对预测下一段最有用」优化的， 原文 KV 从来没有为这个目标优化过——压缩顺带做了去噪。

01状态能一直滚下去

每段 512 token 压成 32 条 KV，下一段带着上一个状态继续压。状态永不增长。 误差复合本来是这个方案最该死掉的地方——每一跳都在重新编码一个已经有损的状态。

02学习率是决定性的，而且非单调

同一模型、同一配置、400 步，只改 lr。峰在 5e-3，两侧掉得很陡。 在此之前的每一个实验都用 1e-3——那是个坏点。

所以「0.6B 太小，学不会自己压缩」是个错误结论。 同一个 0.6B，换对 lr、冻结主干、加深度记忆，1000 步能到 +104%。 此前那张按 lr=1e-3 测出来的规模律表已经作废。

03冻结主干不是妥协

同一 lr、同一步数，唯一区别是主干让不让动。

看 LoRA 那行的 lower：3.951 → 3.370。 LoRA 没在学压缩，它在做语言建模微调，顺手把「什么都看不见」这个基线抬高了 0.58 nats，gap 被挤掉三分之一。

混合条件训练本来就是为了防这个而加的，没防住—— 它把题改简单了，recovery 的分母跟着缩水。主干钉死之后 upper / lower 恒定， 这个比值才真的只反映压缩能力。所以冻结不只是省显存，它是唯一干净的测量。

04深度记忆：给槽位每层一个偏置

P-tuning v2 式。因果注意力保证前面 512 个真实 token 看不见这些位置， 所以主干对普通文本的行为逐位不变——容量全部落在被构建的那个状态里。

flat 0.03M · 400 步 flat 0.03M · 1500 步 deep 3.67M · 400 步 deep 3.67M · 1000 步

k=72 和 k=128 稳定超过 100%——几十个学出来的槽位， 比把 512 个原文 KV 全给它还好用。

同样 400 步，随机预算 +66%，固定 k=32 还在 −38%。 大预算的样本容易学，先把「怎么使用记忆槽」这套机制建立起来，再迁移到小预算。 代价是训久了大预算会反过来抢容量（1500 步 k=32 掉到 +11%，而 k=128 涨到 +89%）。

k=16 在 0.6B / 400 步崩到 −172%，在 1.7B / 400 步直接 +86%。原因是角色冲突：前 16 个槽既要能单独工作， 又要在 k=128 时当整体的一部分，0.6B 的容量不够同时扮演两个角色。

但 0.6B 补步数也能补上（1000 步 +83%）—— 规模和步数在这里可以互换。明确的改进方向是 Matryoshka 式嵌套： 让每个前缀子集都单独计一次 loss。

07被证伪的假设

全部是我自己先提出、然后被自己的实验推翻的。

  1. 必须同时训模型，冻结的读端读不懂合成的 KV 对外挂 encoder 成立，对记忆 token 不成立：状态由模型自己的前向产生，天生在分布内。冻结 +66%，开 LoRA 只有 +8%。
  2. 0.6B 太小，学不会自己压缩 是 lr 选错了。同一个 0.6B 能到 +104%。
  3. 误差复合会让递归压缩崩掉 写在 recur.py 注释里的预判。实测衰减次线性且收敛。
  4. 混合条件训练能防止模型作弊改上界 没防住。LoRA 照样把 lower 抬了 0.58 nats。
  5. RoPE 相位对齐是关键 消融显示关掉几乎无差别（98.4% vs 97.8%）。
  6. 自编码预热能救小模型的紧预算 反而更差，k=16 崩到 −84%。
  7. ppl 能测出抽象记忆有没有信息 probe 显示状态里有信息（48 选 1 达 41.7%），但下游 recovery ≈ 0。信息在里面，接口送不出来。

08那它到底存了什么

记忆槽占着 k 个序列位置、有自己的 RoPE 相位，所以「这不就是把 token 压小了吗」 是个公道的质问。三个探针，每一个都能让「压缩 token」这个假设以不同方式露馅。

探针结果随机基线说明
槽位解码回 token63.3%0.18%带实义关键词
与原文位置的最近邻+0.00 超出—不是任何位置的副本
重建原文+16.3%0还原不了
预测下一段+104%0但极其好用

解码：把槽位的 hidden state 过一遍 lm_head，top-4 里有 63.3% 的 token 出现在原文段落中（随机水平 0.18%，350×）， 解出来的词有实义——计算 / 帧 / 性能。所以槽位确实携带词汇层面的信息。

最近邻：槽位的 key 向量与原文各位置的最大余弦是 0.64–0.81， 看着像「每个槽就坐在某个原文位置上」。但用同一套槽位去压一段完全无关的文本， 数字一模一样（超出量 +0.000 / +0.013 / +0.002）。 那个 0.8 只是「所有 key 都住在同一个窄锥里」的几何性质——随机向量只有 0.02–0.06。 槽位不是任何原文位置的副本。

重建 vs 预测：同一个状态，还原原文只买回 16.3%， 预测下一段却买回 104%。一份有损的文本副本不会有这种落差。

它是笔记，不是录音

笔记上会留关键词，所以解得出实义词；但笔记合成于理解之后， 不对应原文的任何一个具体位置；它还原不了原文，却特别好用—— 因为它从一开始就是为「将来要用」而记的，不是为「存档」而记的。

09下一步

递归结果是 zero-shot 的——训练时模型从没见过多跳。 所以最该做的不是换更大的模型，而是直接训练递归： 训练时就让状态滚 4 到 8 跳，让模型学会「压缩一个已经被压缩过的东西」。 这是整个架构里唯一还没被验证过的部分。

至于规模：35B-A3B 在 bf16 下约需 75 GB 显存，MoE 让它的前向快得像一个 3B dense 模型。 但「规模和步数可以互换」意味着大模型大概率不是「能不能行」的问题，而是「多快到顶」。
